# ANCYA — Architecture

**Status:** implemented on `v2`; the Eleventy build and CI migration is being completed
in the same release. See `PRODUCTION_TODO.md` for the remaining gates.

**Companion to:** `DESIGN_SPEC.md` (rules) and `styleguide.html` (components)

---

## 1. Overview

The site is a static marketing site generated by **Eleventy (11ty)** from `src/` and
deployed to **Cloudflare Workers Static Assets**. One Worker entry point,
`worker/index.js`, handles `POST /api/contact`; every other request is served from the
generated `public/` directory through the `ASSETS` binding.

Design goals:

- Static HTML in the browser: no framework, no hydration, no client-side routing.
- One layout and one set of partials, so the header, footer and sprite cannot drift
  between pages.
- One shared CSS source and small ES modules instead of per-page styles and scripts.
- A hard deploy boundary: Wrangler uploads `public/` and nothing else.
- Security headers defined once for static responses (`src/_headers`) and mirrored by
  the Worker for dynamic responses.

## 2. Source-to-output structure

```
src/                              source (edit here)
├─ _includes/
│  ├─ base.njk                    document shell: head, sprite, header, footer, scripts
│  ├─ head.njk                    meta, canonical, Open Graph, JSON-LD
│  ├─ header.njk · footer.njk     shared chrome
│  ├─ legal.njk                   legal-page layout
│  ├─ sprite.njk                  single source for the SVG symbol sheet
│  └─ cookie.njk                  cookie banner
├─ _data/                         site metadata consumed by templates (URL, contact, analytics)
├─ assets/
│  ├─ css/
│  │  ├─ base.css                 design tokens, reset, typography, layout primitives
│  │  ├─ main.css                 component styles and page compositions
│  │  └─ legal.css                legal-page styles
│  ├─ js/                         site.js, consent.js and shared modules
│  ├─ img/ · svg/ · favicons/ · social/
├─ *.njk                          one template per page (index, about, work, journal,
│                                 services-*, legal pages, 404)
├─ _headers                       Cloudflare static response headers
├─ robots.txt · sitemap.xml · site.webmanifest
│
public/                           generated output (Wrangler assets.directory)
├─ *.html                         rendered pages
├─ assets/                        copied and bundled assets
├─ _headers                       copied from src/
└─ robots.txt · sitemap.xml · site.webmanifest
│
worker/index.js                   /api/contact handler
tests/worker/contact.test.mjs     Worker endpoint tests
scripts/                          link and structural accessibility checks
docs/                             contributor docs and style guide (never deployed)
brand/                            brand source exports (never deployed)
wrangler.jsonc · package.json · .github/workflows/ci.yml
```

`public/` is build output. It is tracked in the repository for review, but it must never
be edited directly: `npm run build` regenerates it from `src/`.

## 3. Build pipeline

1. `npm ci` — install the pinned dependency tree.
2. `npm run build` — Eleventy renders `src/*.njk` through `src/_includes/base.njk` into
   `public/`, and copies `src/assets`, `src/_headers`, `src/robots.txt`,
   `src/sitemap.xml` and `src/site.webmanifest`.
3. `npm run check` — `scripts/check_links.py` verifies every local `href`/`src` in
   `public/*.html` and `docs/*.html`.
4. `npm run check:a11y` — browserless structural checks: `lang`, exactly one H1,
   `#main`, skip link, image alt text and button accessible names.
5. `npm run lint:html`, `npm run lint:css`, `npm run lint:js` — html-validate,
   stylelint and ESLint.
6. `npm test` — Worker unit tests with `node:test` (validation, origin check, body
   limits, honeypot, rate limit, Resend failure paths).
7. `npm run test:a11y` — axe in a real browser (Chrome/chromedriver).
8. `npm run deploy` — Wrangler uploads the Worker and `public/`.

`npm run build`, `npm run dev` and `npm run test:worker` are in place. The lint scripts
and the `npm test` alias are still being wired; the list above is the target pipeline.

CSS is authored in `base.css` (tokens, reset and primitives), `main.css` (components
and page compositions) and `legal.css`. Content pages load `base.css` then `main.css`;
legal pages load `base.css` then `legal.css`. Do not introduce a second component
stylesheet.

## 4. Hosting and request flow

`wrangler.jsonc`:

- `main: worker/index.js`
- `assets.directory: ./public`, `assets.binding: ASSETS`
- `html_handling: "auto-trailing-slash"` — `/work` and `/work.html` both resolve to
  `work.html`; `/` serves `index.html`
- `not_found_handling: "404-page"` — unknown paths render `public/404.html`
- Routes for `ancyatech.com` and `www.ancyatech.com`
- `preview_urls: true`

Request flow:

```
Browser
  │
  ├─ POST /api/contact ──► worker/index.js
  │                          origin check → rate limit → content type → 32 KB cap
  │                          → parse/validate → honeypot → Resend
  │                          JSON response, security headers, no CSP
  │
  └─ everything else ─────► env.ASSETS.fetch(request)
                             static HTML/assets, src/_headers applied by Cloudflare
                             Worker adds baseline security headers to the response
                             404.html for misses
```

Static headers live in `src/_headers` and cover CSP, HSTS, `X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and cache policy. The Worker
mirrors the baseline headers in `setSecurityHeaders()`. The current CSP permits
`'unsafe-inline'`, Google Tag Manager and cdnjs (GSAP); tightening it requires removing
inline scripts and self-hosting the library.

The in-isolate rate limiter in the Worker is best-effort. Production-grade limiting
belongs in Cloudflare WAF rules for `POST /api/contact`.

## 5. Layer ownership

| Layer | Owns | Rule |
|---|---|---|
| `src/_includes/base.njk` | Document shell, meta, sprite, header, footer, scripts | One source of truth. Pages never repeat the shell. |
| `src/_includes/head.njk` | Meta, canonical, Open Graph, JSON-LD | Page front matter supplies the values. |
| `src/_includes/*.njk` | Header, footer, cookie banner, icon sprite | Change once, update everywhere. |
| `src/_data` | Site URL, contact details, analytics ID, social image | Repeated metadata lives here, not in page bodies. |
| `src/_includes/header.njk` · `footer.njk` | Navigation and footer link groups | Change once, update everywhere. |
| `src/*.njk` | Page content and front matter | Content and page-specific structure only. |
| `src/assets/css` | Tokens, base styles, components | Use tokens; no raw hex values or inline `<style>`. |
| `src/assets/js` | Shared behaviour | Small modules; no per-page duplication. |
| `src/assets/img` | Photography and illustrations | Explicit dimensions, alt text, modern formats where possible. |
| `public/` | Generated output | Never hand-edit. Deploy exactly this directory. |
| `docs/` | Design spec and style guide | Updated in the same change as any system change. |
| `worker/` | `/api/contact` only | No static serving, no page rendering. |

## 6. URL strategy

Current public URLs keep the `.html` suffix for compatibility, and Cloudflare also
serves every page without it:

- `/` → `index.html`
- `/about` → `about.html`
- `/services-web-design` → `services-web-design.html` (and the five sibling services)
- `/journal` → `journal.html`
- `/journal-website-cost` → `journal-website-cost.html`
- `/work` → `work.html` (draft, `noindex`)
- unknown → `404.html`

`src/sitemap.xml` lists only indexable pages. `work.html` and `work-foxtail-cafe.html`
are deliberately `noindex` and excluded until the case-study content is approved.
If URLs later move to directory indexes, add edge redirects for the old `.html` paths
and update the sitemap in the same change.

## 7. Continuous integration

CI runs on pushes and pull requests to the release branches:

1. Install and build (`npm ci`, `npm run build`).
2. Link check, structural accessibility check and HTML/CSS/JS linters.
3. Worker tests (`npm test`).
4. Indexing guard: draft pages must keep `noindex`; the sitemap must not list them.
5. Deploy on `main` only after all gates pass.

The deploy job uses the `RESEND_API_KEY` secret in the Cloudflare environment; keys are
never committed.

This is the target pipeline. The current workflow still checks a pre-built page
inventory in `public/`; replacing it with the build-based steps is tracked in
`PRODUCTION_TODO.md`.

## 8. Migration rationale

The previous site hand-repeated the shell, sprite and footer in every `public/*.html`
file. That was acceptable at ~10 pages and one editor but made every nav or footer edit
error-prone and offered no layout-level protection against drift.

Eleventy was chosen over a client framework because it keeps the output static while
adding layouts, partials, data and collections. Astro remains the option if interactive
islands are needed later. The design system did not change: `DESIGN_SPEC.md` and
`styleguide.html` remain the contract, and the generator only removes duplication.

Remaining migration work is tracked in `PRODUCTION_TODO.md`: finishing the build and
lint/test scripts, replacing the pre-migration CI page-inventory checks with build-based
checks, and verifying preview deploy and rollback.
