Ancya style guide

A practical reference for building new pages and components in the Ancya visual language: sapphire and kinetic coral over a cool porcelain canvas, Plus Jakarta Sans throughout, and restrained, purposeful motion.

Source of truth: public/assets/css/main.css Live site: public/index.html Spec: DESIGN_SPEC.md Architecture: ARCHITECTURE.md Updated: November 2026

Colour

Two brand hues — sapphire blue and kinetic coral — sit over a cool, slightly blue neutral scale. Coral is a signal colour: it marks emphasis, the primary action, and the start of a journey. Never use coral for body text.

Layout & spacing

Content sits in a 1200px container with fluid gutters. Sections breathe with a single vertical rhythm token, and grids stay simple: two, three or four equal columns that stack down on small screens.

TokenValueUse
--maxw1200pxContainer maximum width
--gutterclamp(20px, 5vw, 40px)Horizontal page padding
--section-yclamp(72px, 9vw, 128px)Vertical padding for every section
--header-h72px / 64px mobileFixed header height and scroll offset
--r-card16pxCards, panels, image frames
--r-sm12pxInputs, small surfaces
--r-pill9999pxBadges, nav capsule, pills
Ambient texture. Every light section (.band, .band-white) carries a 56px blueprint grid at 4.5% sapphire, drifting diagonally over 45 seconds (::before). Every light section carries decorative line-work via .has-ribbon, alternating between two systems. #services and #blog use the drifting four-line wave ribbon. The other sections get in-place shape fields generated by JS: process and pricing use slowly rotating hexagons, work and about use pulsing circles, and the problem, FAQ and contact sections use a random mix of triangles, hexagons and circles. Shapes vary in size and position, spin or pulse on their own timings, and are masked strongest at the edges and soft behind content. Its mask is inverted: the lines are strongest at the left and right edges and fade to nothing behind the central content column, so the ribbon never competes with text. Both layers sit at z-index: -1 inside an isolated section and stop animating under prefers-reduced-motion. The dark hero instead uses the canvas galaxy with four-point sparkles.

Back to top

A 46px circular icon-only button appears after 480px of scroll, anchored bottom-right (safe-area aware). It is hidden with visibility rather than removed, so it never takes keyboard focus while off-screen, and it moves above the cookie banner on narrow screens.

Static preview

<button class="to-top" id="to-top" type="button" aria-label="Back to top">
  <svg aria-hidden="true"><use href="#i-arrow"/></svg>
</button>

<script>
  var toTop = document.getElementById('to-top');
  var reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
  window.addEventListener('scroll', function () {
    toTop.classList.toggle('is-visible', scrollY > 480);
  }, { passive: true });
  toTop.addEventListener('click', function () {
    window.scrollTo({ top: 0, behavior: reduce ? 'auto' : 'smooth' });
    document.getElementById('main').focus({ preventScroll: true });
  });
</script>

Accessibility

The site targets WCAG 2.1 AA. These rules are part of the component contract, not an afterthought.

  • Focus visibility. Never remove :focus-visible. The global 3px sapphire ring and 3px offset must remain intact.
  • Contrast. Body text uses --body (≈7:1 on white). Muted text is only used for secondary labels and metadata.
  • Motion. All entrance and hover motion is disabled with prefers-reduced-motion; no information relies on animation.
  • Semantics. One h1 per page, sections labelled with aria-labelledby, buttons for actions and links for navigation.
  • Targets. Buttons and nav items are at least 44–48px tall. Mobile menu items are 48px.
  • Forms. Every input has a visible <label>; errors are paired with text, never colour alone.
